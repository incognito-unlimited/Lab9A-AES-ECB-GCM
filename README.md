## ECB vs. GCM — explanation
**ECB** encrypts each 16-byte block independently and deterministically with the same key. Identical plaintext blocks therefore produce identical ciphertext blocks, revealing equality patterns in the input. ECB provides no integrity or authenticity and is not appropriate for general file encryption.

**GCM** is an authenticated-encryption mode combining confidentiality with an authentication tag. It uses a counter mode internally, so identical plaintext blocks do not appear as repeated ciphertext blocks. A fresh, unpredictable nonce must be used for every encryption under a given key; nonce reuse can severely weaken the mode. The tag must be verified (`decryptor.finalize()`) before plaintext is trusted. The nonce and tag are not secret and are stored alongside the ciphertext.

## Security observations
- The ECB test is a direct, observable demonstration of pattern leakage: 24 equal plaintext blocks became 24 equal ciphertext blocks under one key.
- The GCM ciphertext did not show that repeated-block pattern, and the authentication tag detected a single flipped ciphertext byte even though the nonce and tag were unchanged.
- Key secrecy, nonce uniqueness and tag verification are independent requirements: a strong key does not help if a nonce is reused, and encryption without tag verification cannot detect tampering.
- GCM's nonce is not a secret, but it must never repeat for the same key; the program generates a new one per encryption and stores it with the ciphertext.
